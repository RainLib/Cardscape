# 肢体拆层与独立组件预算 · 0.19.67

本轮继续用客户端的 Codex CLI 与 `card-atelier` 制作“星潮守卫 · 肢体景深验证”。原卡保留，所有制作指令由客户端原子应用并写入恢复副本；没有直接修改工程文件来伪造回执。

## 独立素材预算

0.19.66 的实际四项拆层被“工程去重后超过 64 MB 上限”拒绝。正面文档为 48,843,398 字节，绑定独立的共享卡背后为 64,453,776 字节；新人物表面使组合越过 64 MiB。卡背占用了正面的素材预算，尽管二者已经是独立编辑场景。

现在分别检查正面卡和各独立卡背/组件，每个仍为 64 MiB；组合包仍限制为 192 MiB。旧版卡背预览图也计入对应卡背的预算，不能借不同的预览图绕开上限。绑定素材没有删除或降质，母版和现有 Mask 全部保留。禁止组件编辑文档继续嵌套组件，防止通过嵌套绕开预算。去重后存储字节和 GPU 显存不是同一个数值，容量修复不等于渲染性能已达标。

新增回归实际保留 40 MiB 正面与 28 MiB 卡背，验证组合可用且原对象不变；超限正面、超限组件、独立预览图和组件嵌套仍被拒绝。全部 **311 项 Node 测试**与 **187 个 JS 文件语法检查**通过，日志为 `outputs/anatomical-v67/node-tests-final.log` 与 `check-final.log`。

## 角度、动效与导出

实际在客户端检查九个规定角度、0.69/1.05 秒动效和实时播放/暂停。当前预览尺寸下，肩肘、胸甲与握点未见明显新增穿洞；刚性握持组不被衣料网格拉扯。全部 GL error 为 0，人物有 10 次内外绘制；重开后编译 2 次、资源重置 1 次，查看角度及时间未再增加。数值不是 FPS 结论，也不能代替全部极端动作或任意侧面的解剖检查。截图为 `after-rear-support-*.png` 与 `left-up-motion-*.png`。

通过客户端导出整套 Godot 资源，实际导出文件中的主体、握持组、远臂 PNG 与恢复副本逐字节一致，近远分类、深度和刚性配置均保留。证据为 `verification.json`，导出目录也记录在其中；原卡与正式工坊文件摘要没有改变。

在 Godot 4.7.1 / OpenGL / Intel UHD 630 上渲染这份真实素材：九个角度、动效与暂停检查通过，两个刚性组内外共用 6 索引的平面，暂停像素差为 0，角度变化 66,958 像素、动效变化 30,954 像素。没有 Shader 错误；这些指标表明流程与绘制有效，不能作为 Snap 1:1 艺术验收。

首次完整 GPU 测试超过 45 秒；延长上限后整轮完成耗时 54.7 秒。刚性权重扫描改为常见 8 位图像的原始红通道读取并在完全锁定时提前结束，其他格式保留浮点读取；10 个不同格式用例与原算法结果相同。修改后真实素材再次渲染通过，十一张输出的 RGBA 像素与修改前一致。父卡建立耗时 2.245 秒、主体网格 245 毫秒，两块衣料网格约 49/51 毫秒，整轮验证约 54.1 秒。整轮包含多角度绘制、截图编码和像素比较，不能将其当作首帧耗时；首帧与后续步骤另行计时，也没有完成 FPS 基准，不能宣称整体性能已达标。日志为 `godot-mask-equivalence.log`、`godot-gpu-profile.log` 和 `godot-before-after-pixels.json`。
