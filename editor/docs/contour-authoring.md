# 轮廓画布、曲线与 SVG

在卡框面板展开「异形卡体与窗口」，选择外轮廓或某个窗口，在轮廓绘图区选点、拖动或用方向键微调。可在线段中间精确加点，删除锚点，切换平滑曲线／尖角并拖动独立手柄。Shift 拖动吸附 8 像素，Shift 方向键移动 10 像素；滚轮缩放，拖动空白平移，「适合画幅」恢复视野。

所有操作先进入草稿，不在拖动时重建整张卡片或覆盖工程。草稿有独立撤销／重做，在画布内也可用 Ctrl/Cmd+Z；按 Escape 或取消指针操作恢复拖动前的草稿。点击「应用轮廓」才提交一次可撤销的工程修改。工程撤销、重开和组件边框同步均保留锚点与手柄。修改传统宽度／切角会同步默认轮廓；颜色、厚度和动效变化不会重置自定义几何草稿。

「锚点坐标」仍可输入每行 X,Y。直接改某条轮廓的坐标会把它转成折线，其他曲线保留。椭圆预设使用可编辑曲线；增加窗口后可在草稿调整位置，窗口重叠或越界时不会提交。

SVG／路径导入支持绝对与相对 `M/L/H/V/C/S/Q/T/A/Z`，以及矩形（含圆角）、椭圆、圆和多边形；保留平移、旋转、缩放、矩阵及倾斜变换。SVG 使用 viewBox 和 preserveAspectRatio 适合卡幅；原始 d 路径使用 1024×1536 坐标。完整导入按包含关系和嵌套深度识别实体、窗口、窗口内岛屿及更深层窗口，独立外轮廓保留为额外实体；也可以只替换当前实体的外轮廓或当前窗口。重叠路径须先用明确的布尔操作组合。几何导入统一使用嵌套奇偶规则，不解释 SVG 的 fill-rule 或颜色。示例：`examples/contour/dual-window.svg` 与 `examples/contour/complex-islands.svg`。

这是几何导入，不是完整 SVG 外观渲染器：不读取描边宽度、颜色、文本、图片、use、CSS 几何、裁剪／蒙版或嵌套视口。这些对象需要先在矢量软件转换为普通路径。XML 先检查标签与属性，再在独立 DOM 中解析；内联样式改为数据属性后检查，避免触发 CSS 或放宽 CSP。不插入原始 SVG，不执行脚本，不接受事件属性、外部样式指令、DOCTYPE 和实体声明。路径必须闭合；非法数据保留现有工程。弧线转换参考 [SVG 2 路径](https://www.w3.org/TR/SVG/paths.html#PathData) 与 [椭圆弧转换说明](https://www.w3.org/TR/SVG/implnote.html#ArcImplementationNotes)。

保存数据包括 `contour.paths` 中的锚点、入／出手柄和误差设置，以及用于两端渲染的 `outline/windows/islands` 采样折线。自适应细分使用控制点到弦的距离界；误差可设 0.25–32 像素。载入／导出时重新采样并验证两份数据一致，防止陈旧折线与编辑曲线分离。总预算已扩展为 4096 个渲染点、128 条环（实体外轮廓和所有窗口合计），超限明确报错，不静默删点。可删除最后一个窗口，得到实心实体；布尔相减也可得到空轮廓，空结果会保存而不会恢复矩形。`islands` 保存额外实体及各自的 `outline/windows`，曲线元数据中有对应结构；窗口中的实体岛屿可以继续包含窗口。

验证入口：`npm run test:contour-authoring` 实际操作 Electron 的拖动、手柄、微调、缩放、草稿及工程撤销重做、非法输入、SVG、保存重开，再运行导出播放器。设置 `GODOT_BIN` 后运行 `npm run test:contour-godot`。真实验收使用 60 点双窗口，WebGL／Godot 分别以 417 个远离边缘的像素探针与采样几何比对；Godot 同时验证 120 个实体侧壁三角形。截图与日志保存在 `qa/contour-authoring/last-run.json` 指向的目录。本段为基础轮廓阶段记录；后续已接入的倒角、环绕图案与光晕见 [异形边饰与材质](contour-materials.md)。

## 布尔与复杂镂空

展开「导入 SVG／路径与布尔」，输入闭合路径或 SVG，在目标中选择并集（添加实体）、相减（挖空）、交集（保留重叠）、异或（切换重叠）。操作以当前完整草稿为左操作数，导入图形为右操作数；结果可包含多个独立实体或空集，不只保留最大块。上方轮廓选择器可以编辑任何实体的外轮廓和窗口，「删除当前实体」移除当前实体及其窗口。所有操作先修改草稿，可撤销／重做，再一次应用到工程。

布尔操作对当前误差设置下的采样折线运算，计算结果成为可编辑折线；原始曲线可通过草稿撤销恢复。不能把这一点描述为精确的 Bézier 布尔。几何库采用 [polyclip-ts](https://github.com/luizbarboza/polyclip-ts) 的四种 Polygon／MultiPolygon 操作，固定版本 0.16.8，只打包到制作器；播放器使用计算后的几何，没有该依赖。库及依赖的许可证位于 `editor/licenses`。

同一实体内的窗口必须严格位于外轮廓内且互不相交。额外实体可位于窗口中或与其他实体分离；仅接触一点可以保留，共边的区域应先做并集，避免重叠侧壁。自交、重叠、退化、越界和陈旧曲线元数据均会拒绝应用。

## 距离纹理与渲染精度

复杂轮廓阶段使用过注册画幅 1024×1536、±64 源像素的 RGB12 距场。当前所有自定义轮廓统一使用带留白的 v2 距离／环绕坐标图集，默认 2016×1856、±192 源像素；具体布局、缓存预算与旧格式兼容见 [异形边饰与材质](contour-materials.md)。Alpha 固定 255，Shader 用最近邻读取后先解码再插值；PNG 使用无损数据编码、无颜色配置，Godot 采样器不加 source_color。`uniforms.json.frameContour` 提供 texture、fieldAsset、fieldSize、fieldFormat 与 fieldInfo；将 contour-field.png 作为线性数据纹理绑定到 contourField，并设置 contourTexture=1。WebGL 共用单位 7，普通图像仍使用原有单位。

裁剪基于源图像素栅格，距离量化步长约 0.0313 像素；曲线采样误差与像素栅格误差是两件事，不能把小于一个像素的细缝视为可靠可见的镂空。建议可见细缝至少 2 个源像素，放大或打印时按实际导出尺寸检查。几何点与真实侧壁仍完整保留。距离变换参考 [Felzenszwalb／Huttenlocher](https://www.cs.cornell.edu/~dph/papers/dt.pdf) 的采样函数欧氏距离变换；每次几何变化才计算，帧内不逐边遍历复杂轮廓。CPU 保留最多 4 份距场（约 24 MiB 原始像素）；同一 GL 上的多个渲染器按几何共享上传，最后一个引用销毁时释放纹理，重置工程也会释放。距场不经过清晰度降采样，远端依赖按内容摘要去重。

验证命令为 `npm run test:complex-contour`，随后设置 GODOT_BIN 执行 `npm run test:complex-contour-godot`。实际 Electron 验收四种布尔、拆分实体、空草稿、实体删除与撤销、选中额外实体、保存重开及独立播放器；基础样例为 164 点六窗；实际通过布尔相减新增一窗后保存重开的 168 点七窗、带孔岛屿与独立实体，由两端分别通过 402 个远离边缘的透明度探针，并与浏览器原生 SVG 对照。Godot 验证 336 个真实侧壁三角形，以及导入后 32 个距场像素的 128 个通道字节未变化。最新产物见 `qa/complex-contour/last-run.json`。本段为复杂轮廓阶段记录；后续材质适配与独立验收见 [异形边饰与材质](contour-materials.md)。
