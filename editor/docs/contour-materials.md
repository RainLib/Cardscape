# 异形边饰、倒角与光晕

在边框面板应用轮廓后，仍可选择既有的 25 种边饰与呼吸／流光／幻彩动画。程序化颜色改用实际轮廓的边缘距离与闭合弧长，外轮廓、窗口、嵌套岛屿和独立实体分别生成环绕坐标；不再把矩形四边直接投射到异形框面。每环从最上方、最靠左的顶点顺时针起算，调整输入顶点顺序或方向不会反转流光。短环会压缩原边饰的重复图案，建议避免低于两像素的细节。

环绕图案在边缘带内逐渐过渡到连续的框面底色与反射。宽框面中部不使用最近环的相位，避免最近边界切换时出现放射状接缝；细梁两侧的图案仍按各自边界环绕。

光晕围绕真实实体边界生成，包含窗口内部与岛屿周围，范围沿用各边饰的 88／144 像素限制。2D 制作封面与动态预览共用材质函数；图片边饰、人物插画及自定义图层仍使用原画幅 UV，不跟随程序化材质的坐标重映射。图片组件自己的 Shader 继续控制其流光。

倒角生成真实斜面。先计算轮廓内缩与剩余边带，再三角化有孔区域，补入窄横梁的中脊，并自适应细分斜面。面、背面与全部侧壁在边界处闭合；倒角不超过厚度的 45%，避免薄卡正背面相穿。完全消失的内缩区域保留中脊，不退化成一张平面。原始轮廓的点接触表示多个闭合实体接触，挤出后会形成共位的竖边。

当前倒角高度采样以源像素为单位，细分误差上限 1.2 像素，每个框面最多 65000 顶点，细分种子最多 24000。超过预算会在文档事务应用前报错，可减小倒角或简化轮廓；不自动替换用户轮廓。重复预览复用按轮廓与倒角参数缓存的网格。轮廓点／环预算仍为 4096／128。

## 数据纹理与导出协议

新导出包在 manifest 写入 `contourFieldFormat: card-contour-field-atlas/2`，在 uniforms.json 写入 `frameContour.fieldInfo`。默认纹理是 2016×1856：左侧 1344×1856 存储两路 RGB12 有符号距离，右侧 672×1856 存储 RGB16 周长相位及环编号／窗口标记。距离区与坐标区均包含 160 源像素留白，距离范围为 ±192 像素；颜色通道是数据，alpha 固定为 255。距离量化步长约 0.094 像素，弧长图的横向步长为两像素。

纹理必须保持无损、原尺寸、最近邻读取及线性数据语义。Shader 先解包四个像素，再插值距离；相位插值处理闭环接缝，并避免混合不同环的编号。不能交给图片缩放、sRGB 转换或有损压缩流程。PNG、远端依赖与 Godot 资源都保留这份数据。

CPU 距场缓存最多四项，满尺寸约 57 MiB；每个 WebGL 上下文中的拥有者共用同一轮廓纹理，最后一个拥有者释放时删除纹理。新框面库随独立播放器一并导出，不需要运行时安装 npm 依赖。Godot 使用导出的相同几何与贴图。

请将新资源与同次导出的 SDK 一起交付。新 SDK 也识别旧 1024×1536、±64 像素的 RGB12 距场，继续使用旧 UV 与距离范围；旧 SDK 不具备新版图集的读取能力。没有 WebGL 的 Canvas 降级保留框面与裁剪，不提供完整程序化光晕。
