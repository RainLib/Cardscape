# Adamantium：成长减速方案

## 可观察的差异

参考仍为 SnapFan Adamantium 的 77 帧公开序列。查看完整图标的连续局部图后，半径增长具有明显减速：例如第 86 条轨迹半径依次为 24.4、30.1、34.3、37.4、39.0 px，每两个样本相隔 0.06 秒。第 41 和第 5 条轨迹同样在后期放慢。

39 条参考轨迹中，38 条二次拟合的曲率为负；卡宽归一后的二阶导数 P10 / P50 / P90 为 `-1.87734 / -0.76367 / -0.37638`。二次拟合的中位残差为 `0.000448` 卡宽，直线拟合为 `0.001859`。当前 0.19.83 的尺寸函数是线性增长，因此这部分视觉节奏尚未对齐。

证据为 `outputs/emblem-v84/reference-growth-strips.png`、`growth-diagnosis.json` 和 `curvature-diagnosis.json`。二次拟合不是原始引擎曲线；裁剪、重叠与不完整生命阶段仍会影响结果。保留全部轨迹，不为了降低误差删掉异常轨迹。

## 先试验，再采用

保持已校准的径向速度、出生位置、发射面、数量、寿命与 Alpha 渐隐。独立比较页只在进入真实生产 GPU Shader 前替换尺寸因子，明确标记为实验曲线，不替换活跃工程。

令 `p` 为当前生命阶段、`q=clamp(p/span,0,1)`、`ease=q×(2-q)`。试验三种参数：

| 方案 | 起始因子 | 成长幅度 | span | 大图标尺寸组 |
|---|---:|---:|---:|---|
| balanced | 0.40 | 0.40 | 1.00 | 0.92 + 0.33 × sizeSeed |
| spread | 0.40 | 0.42 | 1.00 | 0.66 + 0.82 × sizeSeed |
| earlier | 0.36 | 0.46 | 0.85 | 0.72 + 0.72 × sizeSeed |

尺寸是 `尺寸组 × (起始因子 + 成长幅度 × ease)`。较宽尺寸组用于弥补减速曲线压窄尺寸分布的影响；它仍需真实像素证明有效。小伴随图标保留原来的尺寸组。

使用相同的 77 帧采集与检测算法比较速度、尺寸分布、增长率、曲率、增长比和可见数量。不以减少可见数量直接推断寿命，不把单一误差下降当作整体验收通过。如果候选破坏已校准的尺寸或速度，则继续调整或保留生产基线。

## 第四个方案：分别控制出生和峰值

前三个候选的曲率误差分别为 `0.69961 / 0.69095 / 0.52282`，低于线性基线的 `1.00506`，但成长比分位数误差为 `0.24636 / 0.22975 / 0.22021`，均高于基线的 `0.19974`。balanced 的尺寸误差增加到 `0.003059`，因此不采用。spread 与 earlier 的尺寸误差仍为 `0.001446 / 0.001418`，高于基线 `0.001071`。这些变化来自真实 GPU 的 77 帧，未据此修改生产。

参考轨迹的首次可见半径 P10 / P50 / P90 为 `0.02485 / 0.02813 / 0.03343` 卡宽，末次为 `0.03316 / 0.05000 / 0.06109`。这说明需要试验接近的出生尺寸和不同的成长幅度；统一曲线乘以尺寸组同时改变出生与峰值，不能解释这一差异。可见半径仍不是实际出生、死亡尺寸，这只是候选的依据。

新增 varied 独立试验：大图标以原来的独立 `sizeSeed=h` 控制成长幅度 `0.20+0.65×h` 与达峰阶段 `0.95-0.40×h`，出生因子固定为 `0.30`；`q=clamp(phase/span,0,1)`，尺寸因子为 `0.30+amplitude×q×(2-q)`。小图标保留尺寸组，使用 earlier 的曲线。发射位置、生命周期、径向移动和 Alpha 都不变化。先检查完整图标的尺寸、成长比分布和曲率，再考虑生产采用；不将 extrapolation 当作源引擎参数。

varied 的实际 GPU 结果：成长比误差 `0.17232`、增长率误差 `0.01708`、曲率误差 `0.31093`，三项均低于线性基线；67 条保留轨迹全部向外且减速。尺寸误差为 `0.002105`，主要差异是低分位图标偏小，因此仍不直接采用。

## 第五个方案：根据观测规划参数

将 varied 的实测图标中心与原始采样投影进行匹配，仅对距离小于 3 px 的 764 个点、66 条完整轨迹做参数预测。预测使用同一组已可见点，无法预测新尺寸造成的遮挡、边界裁剪和检测变化，因此不能作为 GPU 验收。原始参考的 39 条轨迹和正式检测器没有删改。脚本与结果保存在 `outputs/emblem-v84/predict-growth.py`、`matched-growth-prediction.json`、`quadratic-candidate-prediction.json`。

下一次独立 GPU 候选 fitted 将预测参数取整：出生 `0.38`、成长幅度 `0.20+0.77×h^1.58`、达峰阶段 `1.03-0.27×h`，仍为二次减速 `q×(2-q)`；小伴随图标不变。拟合是新的实现方案，不是源引擎参数。仍需重新采集 77 帧，正式比较尺寸、增长率、增长比与曲率，并保留不完整生命周期的验收限制。

## 实际渲染验证的范围

前三个候选与 varied 都已由浏览器下载完整 77 帧。fitted 的浏览器页面返回采集完成，但下载没有恢复，因此不记为该方案的 WebGL 像素验收。

增加 `scripts/probe-emblem-godot.gd`，从 QA 页面生成器旁的 `.samples.json` 读取同一组 JS 样本，以生产 Godot 粒子 Shader 和固定 MultiMesh 实际渲染 baseline 与 fitted，各 77 帧。相机、820×1000 输出、根级缩放与位置和卡宽归一方式与 WebGL 对照页一致。该步骤验证采样表经过 Godot Shader 后的像素变化，**不证明 Godot 的运行时轨迹采样器已匹配新曲线**；采用后还必须单独运行跨引擎 `test_particle_reveal.gd`。

首次原生窗口采集在 57 帧后达到 120 秒超时，不记为通过。完整序列改用独立 `SubViewport` 和显式 `RenderingServer.force_draw(false)`，避免依赖原生窗口的下一次绘制回调。API 依据 [RenderingServer](https://docs.godotengine.org/en/stable/classes/class_renderingserver.html#class-renderingserver-method-force-draw) 和 [SubViewport 更新模式](https://docs.godotengine.org/en/stable/classes/class_subviewport.html#enum-subviewport-updatemode)；这仅是验证脚本，未改变客户端的运行逻辑。

`scripts/package-emblem-godot.cjs` 必须读取成功 GPU 日志、相符的参数元数据、77 张真实 820×1000 PNG 后才生成检测输入。它原样保留 PNG 字节，并记录渲染器、输入文件和哈希；不能从 CPU 数据合成像素代替采集。正式比较仍使用未改变的检测器和全部参考轨迹。

## 采用结果：0.19.84

独立目标首次运行返回完整 154 帧，但逐像素检查发现 baseline 首帧为空；`godot-candidate-offscreen/`、`godot-baseline-*`、`godot-fitted-*` 的这一轮不作为采用依据。保持时间点不变，增加首次绘制预热、CPU/GPU 同步和首帧黄色图标非空校验后，重新采集全部 154 帧。有效证据以 `godot-candidate-warmed/` 和 `godot-warmed-*` 为准。Godot 4.7.1 / AMD Radeon Pro 5500M / OpenGL Compatibility 返回通过，Shader 错误为零；79.996 秒是整项采集耗时，不是实时 FPS。

有效 baseline 首帧与此前 WebGL 0 秒帧的整幅 RGB 平均绝对差为 `0.09168 / 255`，图标区域为 `0.83741 / 255`，证明对照注册和时间点成立。数据见 `renderer-warmed-baseline-pixels.json`；它比较当前两个渲染器，不代表与 Snap 原画逐像素相同。

| 观测误差 | 线性 baseline | fitted | 减少 |
|---|---:|---:|---:|
| 半径分位数 / 卡宽 | 0.001071 | 0.000869 | 18.86% |
| 末次 / 首次可见半径比 | 0.199803 | 0.123657 | 38.11% |
| 半径增长率 / 卡宽 / 秒 | 0.034539 | 0.012806 | 62.92% |
| 半径二阶导数 / 卡宽 / 秒² | 1.005296 | 0.476694 | 52.58% |

fitted 的 65 条保留轨迹全部向外且减速。速度分位数误差从 `0.001561` 变为 `0.002356`，并没有改善；尺寸变化会影响检测位置和保留样本。实际生产采样与候选 GPU 输入的 77 帧、40 个实例、10 值顶点布局逐项比较，**所有字段的最大差都为零**，包括大小；物理位置、Alpha、角度和种子没有变化，见 `production-sample-parity.json`。因此采用的是已经实测的成长曲线，未改变已经校准的移动函数。

28 项相关 Node 回归通过，新增可见期间成长率递减与独立成长幅度验证，并保留长时间外扩、出生渐隐、区域／卡背绑定、质量预算、固定批次和共享图标的回归。构建与语法检查通过 200 个文件，`git diff --check` 通过。

使用真实 `exportGodot` 导出独立 0.19.84 场景（一张验证卡、零纹理），运行 `test_particle_reveal.gd` 通过，实际 GPU Shader 错误为零。该测试逐项比较 Godot 运行时 MultiMesh 与编辑器采样的尺寸、位置、Alpha、朝向与数量，覆盖 Adamantium 三种发射形状以及 0 / 0.7 / 100 / 86400 秒，检查暂停、正面限制、共享时钟与预算。日志为 `godot-runtime-parity.log`，截图为 `godot-runtime-captures/`，导出为 `godot-runtime/godot/`。42.681 秒是验证任务耗时。

参考可检测数量中位数仍为 7，当前为 10；可见时长误差仍为 `0.038` 秒；最强减速分组和完整游戏生命周期仍不匹配。公开片段仅 2.31 秒，不能据此证明完整游戏回路、遮挡或所有随机种子。`accepted_1_to_1` 保持 `false`，全量 Snap 与每类至少 50 个原创效果的目标仍在继续。

本轮没有替换活跃卡片，没有修改当前星辉边框、费用或战力，也没有重启独立 Electron 窗口。生产源代码和构建版本为 0.19.84；未记录拟合方案的浏览器下载成功或新版本客户端视觉验收。
