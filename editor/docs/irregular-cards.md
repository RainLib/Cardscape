# 异形卡、动画层序与动作过渡

2026-11-02，第一期。目标是让异形卡的结构、遮挡和动作在编辑器、独立 WebGL 播放器与 Godot 中共用数据。旧工程缺少新增字段时，维持原有卡框和即时动作切换。

## 制作入口

1. 在卡框面板选择并解锁卡框，展开「异形卡体与窗口」。可从椭圆窗口、盾形卡体、双窗口开始，再逐行修改 X,Y 坐标。「应用轮廓」一次提交，支持撤销、重做；「恢复默认卡体」恢复旧卡框。
2. 坐标使用原画注册画幅 1024×1536，外轮廓和窗口都可以是凹多边形。总计最多 4096 个采样顶点、128 环，支持额外实体与窗口内岛屿。窗口必须完全在外轮廓内且互不相交；重复、共线、自交、越界、重叠和退化轮廓会拒绝应用。画布支持曲线手柄与 SVG，布尔与预算说明见 [轮廓编辑](contour-authoring.md)。
3. 图片边框也可设置承载轮廓和窗口，父卡与内嵌组件同时更新。此操作不重绘或拉伸原边框图片，图片装饰需要与新窗口相适配。
4. 在动画时间轴展开「动画层序与切入过渡」，定位时刻、选择并解锁人物或普通图层，再记录置前／置后。记录初始层序可在当前时刻恢复图层列表顺序；删除当前层序帧后，沿用此前的层序。背景、卡框与材质底仍使用各自的绘制阶段。
5. 「切入过渡」设置当前动作从其他动作切入的秒数，范围 0–2，0 为直接切换。可在效果预览或导出播放器中播放不同动作检查衔接。时间轴定位和草稿试姿势直接显示目标时刻，不叠加过渡。

## 数据与运行规则

新增可选字段，无需迁移旧文件：

```ts
frameStyle.contour = {
  outline: [[x, y], ...],
  windows: [[[x, y], ...], ...]
};
actions[i].drawOrder = [
  { at: 0, layers: ['body', 'hand'] },
  { at: 0.5, layers: ['hand', 'body'] },
  { at: 1, layers: [] }
];
actions[i].transitionDuration = 0.35;
```

轮廓顶点不重复首尾点。单个实体的窗口采用分离的简单多边形；窗口内可加入 islands 实体，该实体还可继续包含窗口。`contour` 显式覆盖参数化卡框的外形和窗口，旧 `shape` 字段的兼容行为保留。异形框的框面为平面，外边与各窗口有实际厚度侧壁；宽度、切角和倒角控件不再决定异形几何。自定义轮廓暂不生成程序外沿光晕；现有图案和材质按卡幅映射，不保证原有沿矩形边框的特效自动沿任意曲线重排。复杂边饰可使用独立透明图片层。

自行接入导出的 GLSL 时，`uniforms.json` 的 `frameContour` 提供 `counts` 与补齐至 64 条边的 `edges`，对应 `contourCounts`、`contourEdges[0]`；复杂轮廓还提供 texture、fieldAsset 与 fieldSize，texture=1 时必须按 [距场协议](contour-authoring.md) 绑定 contourField 并设置 contourTexture。坐标已转换为卡片空间；未启用轮廓时 counts 为零、edges 为空，继续使用旧裁剪。

CPU 的点内判断、2D 窗口及破框裁剪、框面栅格与命中检测使用同一轮廓。简单轮廓使用最多 64 条注册边；复杂轮廓使用共享的无损距离纹理，模型和侧壁预算为 4096 点／128 环。框面以两个三角形承载，通过轮廓裁剪，侧壁沿真实边生成。普通卡背和图片分层卡背按父卡外轮廓裁剪；完整自有卡背场景保留自身工程轮廓，需要分别配置与验收。原有内外双通道和破框 Mask 保留，空间 Z 不由绘制顺序改写。

`drawOrder[].layers` 按先绘到后绘排列；未指定的图层保持原来的列表槽位，空数组恢复初始顺序。`at` 为动作内 0–1 的归一化时刻，严格递增，最多 64 帧；层序使用保持插值。保存、打开和导出校验引用，删除图片层时清理其层序、透明度和 FFD 引用。循环、倒序定位和暂停均由当前动作时刻确定，不依赖上一帧。Spine JSON 的 `drawOrder`／旧 `draworder` 偏移与重置帧转换为原生层序，未映射图层保留位置。

过渡冻结开始时实际显示的源动作采样，目标动作继续计时，权重使用 smoothstep。混合整卡变换、局部骨骼变换、IK 目标及权重、表情、图层透明度与 FFD；先混合局部通道，再解骨架，避免矩阵直接混合缩短骨段。FFD 按稀疏顶点索引合并，缺失通道向零形变过渡。层序在混合权重 0.5 切到目标层序。新动作打断过渡时从当前混合结果重新采样；暂停冻结过渡；定位、停止或切换工程取消过渡。目标动作即使短于过渡，也在过渡结束后才完成。Godot 的 `play_action(id_or_event, transition_seconds = -1)` 可覆盖工程时长，负数沿用工程设置。

轮廓改变才更新框体几何与轮廓数据；层序和动作过渡不重新生成图片或网格。暂停时保持时钟与画面稳定，网格资源继续复用。Godot 根据混合后的实际根变换选择清晰度档位，避免切入放大动作时提前按目标缩放选档。

## 验证与交付边界

回归入口：`tests/irregular-card.test.cjs`、`tests/preview-playback.test.cjs`、`tests/spine-import.test.cjs`、`tests/frame-panel-artwork.test.cjs`。覆盖非法轮廓的原子拒绝、凹轮廓与多窗口、层序引用、循环定位、混合端点、连续打断、短动作、暂停及稀疏 FFD。

独立 GPU 验证使用 `node scripts/smoke-irregular-card.mts`，真实导出一张色块功能卡，保存重开后检查轮廓与动作不变；读取实际 WebGL 像素验证透明凹角、两处窗口、框体横梁和动态遮挡，检查过渡起点、暂停、中断及完成。静态 `front.png` 在该专用夹具中使用占位封面，不将它计为完整成品卡面验收。结果在忽略的 `qa/irregular-card-2026-11-02/`。

Godot 导出项目先完成资源导入，再用 `scripts/test-godot.cjs --project <导出项目> --script tests/test_irregular_card.gd` 执行 GPU 验证。用真实渲染检查相同的双窗口与层序、卡背轮廓、过渡连续性及网格复用。桌面生产／开发 smoke 同时检查实际制作控件的应用、撤销、重做、无效输入保护与动画字段。

首轮使用几何色块验证制作与运行能力；后续已新增星炉哨卫真实拆层样卡及动作粒子事件，两端实际导出结果见 `production-readiness.md` 与 `action-particles.md`。仍待扩展贝塞尔曲线直接编辑、任意复杂镂空／布尔运算、完整 Spine 约束及颜色轨道、世界坐标历史拖尾、音效与多动作叠加混合，以及移动设备多卡性能。独立透明装饰可以超出卡体；本轮不把 2.5D 分层卡升级为任意实体模型，也不承诺所有视角的自动穿插修复。
