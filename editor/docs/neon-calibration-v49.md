# 0.19.49：霓虹框局部校准与效果预览提交

## 预览更新

0.19.48 保留同一卡片的视角、动作和资源。进一步检查发现，效果库切换同类候选及应用候选时，会先恢复原配方，再更新新配方；宽度不同的卡框因此重复重建网格。

0.19.49 同类候选直接替换预览值，应用时先写入卡片，再移交给卡片实际组件。关闭未应用的候选仍恢复进入效果库之前的预览；提交失败仍保留完整候选。不同种类的候选会清除上一种临时效果。

真实编辑器中，旧逻辑应用候选使框网格累计计数从 11 增至 19。新逻辑的冰蓝 → 绯红 → 冰蓝 → 应用保持 11；纹理 18、Shader 编译 2、场景资源重置 1 均不变，视角 −18°、播放时间从 96.275 s 持续到 101.585 s。首次将原框改成较宽的霓虹框，仍需要更新相关的四个框网格。

## Snap 霓虹框局部校准

参考：[SnapFan NeonBlue](https://snap.fan/cosmetics/borders/NeonBlue/) 的公开短序列。参考像素仅供分析，不进入工坊素材或导出资源。

- 取首帧右侧未被人物、字标和数值遮挡的直边，106 条扫描线。
- 参考蓝绿通道均大于 235 的亮芯中位宽度 22 px；参考卡宽约 650 px，属于图像估计值。
- 生产 Shader 的同类亮芯从 10 / 1024 增至 34 / 1024。相对卡宽的绝对差从 0.02408 降至 0.000643；不能把这一项误差当作整卡相似度。
- 核心平均 RGB：参考 188 / 252 / 252，校准后 193 / 254 / 255。使用宽发光面与两条细亮边，视角影响局部反射；没有新增自动脉冲。
- 新建／应用霓虹配方使用 42 px 框宽。已保存卡框的自定义宽度保持原值。六种配色共享该结构，但只对冰蓝进行了参考测量。
- 无新增纹理、节点或绘制批次。框几何保持平直切角，外晕继续复用既有窄带。

内侧光溢出、完整游戏相机和待机序列，以及其他配色的逐帧对照仍待校准。`accepted_1_to_1` 保持 `false`；原创扩展仍为 4 / 60，未以霓虹变体充当原创数量。

## 验证

274 项回归、164 个文件语法检查通过。新增检查覆盖同类候选切换、取消、提交失败、无过渡旧场景、自定义宽度保存，以及 WebGL / Godot 函数一致。

编辑器实际导出 1 张卡、14 个共享资源、54 个去重文件。导出 SDK 的 `card_surface.gdshader`、`card_particles.gdshader`、`cardscape_card.gd` 和 `cardscape_library.gd` 与源文件逐字节相同。

Godot 4.7.1、OpenGL Compatibility、Intel UHD Graphics 630 实际 GPU 验证六种霓虹配色：待机静止、视角反射、暂停、框内空白、翻背光晕隐藏、网格复用均通过；无 Shader 错误。冰蓝亮芯平均宽度 / 投影卡宽为 0.03372。测试使用实际工坊导出与由编辑器配方生成的框几何，没有修改生产渲染器。

证据：`../outputs/neon-v49/evidence.json`、`editor.png`、`calibration.png`，Godot 日志 `../outputs/neon-v49-godot.log` 与 `../outputs/neon-v49-godot-captures/`。UI 操作来自与 Electron 共用的编辑器页面；未声称自动点击独立桌面窗口。
