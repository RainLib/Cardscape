# Neon Trails 连续运动校准 · 0.19.92

先按官方连续画面确定运动设计，再修改生产预设。参考是 MarvelSnap 官方《Character Mastery Walkthrough》视频 https://www.youtube.com/watch?v=w2e4TfaTu60 ，本地源 SHA256 为 `5cb799d64ad3c555c4f0551d70db6347530d3250e76b03d94f3f5a853d4700d8`。

181.033–182.8 秒抽取 53 帧，51 帧通过人物内部特征的相似变换配准。P10/P50/P90 配准误差为 0.253/0.524/0.652 像素。遮掉原画、数值与字标后，早段光束外端速度为 1.326/1.477/1.657 卡宽每秒，后段为 0.428/0.580/0.676。量测分别保留 10 条早段和 4 条后段轨迹，最高检测到 21 个独立线段，181.6 秒的框外亮像素最多。

原预设的所有光束同时出生，1.4 秒只移动半个卡宽，无法形成这种快速移出与较慢尾段并存的效果。本轮设计为同一批次里的两组错峰射线：多数早段快速移出，少数延后出现且更短、更慢，保留白色中心与彩色边缘。初始拟合经过实际 GPU 复验后，最终参数为 32 条、1.6 秒、2.8 卡宽行程、0.5 错峰比例、0.0525 尺寸与 8 倍拉伸。后段出生位置靠近内框边缘，避免被原画完全遮住；后段速度系数为 0.38–0.48。参数只表示重建模型，不代表已取得游戏内部参数。

新增 `reveal.profile=burst|trails` 和 `reveal.stagger`，旧工程缺省仍为 burst/0，旧闪光运动保持原值。行程上限提高到 3 卡宽，受固定粒子数量和时长限制；不增加贴图、场景节点、顶点布局或绘制批次。客户端和 Godot 采用同一组种子及公式。控制位于折叠的“揭示闪光”内，选择霓虹射线才显示错峰比例。

可见光束长度受到卡片遮挡，不能直接当成实际几何长度；可见时段也不是完整生命周期。连续图像支持后段仍有短射线，尚不能排除低频待机射线，因此一次性机制仍是待进一步验证的假设。检测数是可见下限，不是发射总数。前一轮自由单应变换造成后段图像失真，已明确拒绝并存档，不用于调参。

验收需分别记录生产 GPU 运动、参考统计、真实客户端保存重开和 UI 导出、导出 Godot 采样与 GPU。以上量测不能独自证明同场景逐帧 1:1；覆盖表保持 `accepted1to1=false`。不修改用户原工坊。

实际生产 WebGL 对照：早段速度 P10/P50/P90 为 1.313/1.451/1.647 卡宽每秒，后段为 0.531/0.587/0.665。早段保留 11 条轨迹，后段 5 条；早段中位速度相对参考误差约 1.8%，后段约 1.3%。旧预设早段中位速度只有 0.143，未检出后段轨迹。当前最高检测 25 条，参考 21 条；测试卡面遮挡不同，不能据此判定总数量还原。

同源客户端实际应用预设、切换运动类型、修改错峰比例、保存、回到首页重开，并通过界面导出；大小 0.0525 的数值框验证有效。揭示期间 32 个粒子、1 次绘制，复用 61440 字节缓冲；结束后 0 个粒子、0 次绘制。导出播放器的暂停时钟不变，继续播放时钟推进。独立 Electron 窗口未进行本轮 UI 自动化。

提交前 Godot 回归发现 inspect 翻面后粒子显隐需要等待 _process，改为显式调整视角时立即调用更新，新增不等待帧的背面零粒子断言。实际从客户端重新导出的 SDK 通过 GPU 回归，跨渲染采样、暂停、预算与立即翻面均通过，Shader 错误为 0；结果保存在本地 verification.json；若重放验证，需自行从上述官方视频生成本地参考，不随仓库提交视频或 QA 产物。
