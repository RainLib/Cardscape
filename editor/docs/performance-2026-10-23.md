## 实现

1. **卡框 Shader 按 finish 特化并按需编译。** `rendering/shader-variants.ts` 只处理内置卡框的已知 finish 条件，保留仍可达的共享函数。平面卡框的光栅片段源码由 56,070 缩至 4,466 字符，诊断主片段由 61,931 缩至 28,445 字符。输出仍使用原有程序化效果，不以简化 Canvas 图形替代。主预览保留最多四个程序的 LRU，复用对应属性和 uniform 位置，切回近期样式无需再次编译；淘汰、原始程序替换及销毁都会释放资源。
2. **首页延迟创建主预览。** `rendering/lazy-preview.ts` 在首页只记录 active、特效和缩放设置，首次处理工程时才创建主预览 GPU 资源。工程预检直接使用目标工程解析后的 finish，避免先编译默认 finish、正式加载时又编译一次。编译错误仍发生在替换工程之前。
3. **隐藏空间视图跳过刷新，缩略图按内容失效。** `space-view.ts` 隐藏时不重建节点、控件或 PNG；切入时从当前工程刷新。文字缩略图依据文字、样式、字标和语言失效，修改工程名称不再使它重编码。打开未修改的内嵌 Mask PNG 直接保留编码字符串，空白同色 Mask 只编码一次。
4. **Mask 覆盖图延迟分配。** 编辑所需的原像素仍立即读取；覆盖 Canvas 和 `overlayPixels` 首次显示或绘制时生成，并复用同一对象。7 张 1024×1536 覆盖图少分配的 RGBA 数组为 `7×1024×1536×4 = 42 MiB`，尚未计入覆盖 Canvas 的后备存储。初始 Mask 权重更新合并为一批；此数字不是整进程内存下降量。

用户 GLSL 钩子保留原文；显式或经宏引用 `rimColor`、`rimAura`、`rimCoverage` 时保留完整程序，以保持参数语义。直接传入的原始 `compileSources` 也不裁剪输入。复杂自定义 Shader 的首次编译仍可能较慢。

## 测量条件与范围

时间指标使用 Windows、Electron 44.7.0、electron-vite **生产构建**，默认 GPU 参数。实际 WebGL 渲染器为 **Intel UHD Graphics / ANGLE D3D11**；SwiftShader 仅用于视觉和功能回归。

窗口 1560×1020、像素比 1；每轮使用独立应用资料目录。采样窗口透明、不抢焦点，等待加载窗结束后关闭后台节流。动态采样确认页面未隐藏、预览 active，并以真实重绘事件及时间推进校验。系统磁盘缓存未清除，CPU Profiler 和 API 计时存在开销，结果是本机对照，不是所有硬件的性能承诺。

动态样卡使用项目自带人物、背景、卡背和 Mask 素材，以 authored / legendary / idle 运行，7634 三角形。优化前动态样卡来自只跳过隐藏空间视图刷新的诊断进程；最终复测没有跳过、回退或替换业务路径。两者的帧间隔中位数为 36.3 / 36.4 ms，P95 为 37.6 / 37.8 ms，均没有 >50 ms 主线程长任务。这里统计的是重绘事件频率，不是 GPU 呈现 FPS。

短时采样中，播放、暂停和改名期间没有持续新增纹理上传、Shader 编译或网格创建；这不构成长期无泄漏证明。本轮没有覆盖大型多卡工坊、极端 Spine/粒子压力或长期导出吞吐量。

本地原始记录位于 Git 忽略的 `qa` 目录：`performance-before-original.json`、`performance-optimized-final.json`、`performance-optimized-art-final.json`、`performance-shader-parity.json` 和对应 `*-final.log`、`.cpuprofile`。采样入口为 `node qa/profile-desktop.mjs --label=optimized-final`；加 `--animation --label=optimized-art-final` 运行素材样卡。最终结果没有启用 `--skip-space` 或 `--fallback-frame` 诊断参数。
