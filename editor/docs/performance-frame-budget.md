## 修改和适用范围

在解码后的静态原画上扫描所有非零 Alpha，给包围矩形外留两个解码像素；着色器在首次取样之前排除矩形外的确定透明区域。保持原配准、UV、Clamp-to-edge、正背面镜像、骨骼、FFD 和网格不变。仍执行原 Alpha 阈值判断。程序化边框、允许透明覆盖的自定义 Hook 与替换背景继续按原规则处理；旧手工 Shader 调用未设置私有 uniform 时关闭这项优化。

Web 只缓存相同 HTMLImageElement／源地址／尺寸的解码，与现有不可变图片上传约定一致；弱引用不持有额外图片所有权。Canvas、ImageData 等可变源，以及不可读取的图片回退为完整范围。单图扫描上限为 16M 像素，临时 Canvas 清空后释放，不在逐帧绘制中读回像素。Godot 仅优化导入的 CompressedTexture2D，数字矩形缓存最多 64 项；可变 ImageTexture 和当前远端图片走完整范围，因此不声称远端也取得这项性能收益。

## 测量口径

- Windows 11、i7-14650HX、Intel UHD / ANGLE D3D11、Electron 44.7.0，1280×900、DPR 1，共享 GL 上下文。静音，均衡调度目标 30。固定小图保留完整效果；自动档按项目原有规则降低效果，两档不可当作相同质量。
- 系统电源方案为 Silent，观察时连接交流电；本阶段没有改变电源方案。未控制 GPU 时钟、温度、其他进程和驱动缓存，因此保留多轮波动，不只挑选最快记录。
- CPU 是宿主提交耗时；GPU 通过扩展计时器每十次提交采样一次，最多四个待取查询，不代表每个显示帧都采样。纹理是 GL 分配估算，另有进程和 Windows GPU 计数，不替代驱动显存。
- 新增 `--presentation-trace`：窗口不透明、置顶、不抢焦点；在同一渲染进程的稳态起止标记内统计唯一显示流的 `Display::FrameDisplayed` 时间戳。排除加载、销毁和重复时间戳，拒绝多窗口或歧义显示流。它是 Chromium 呈现反馈，不是 JavaScript 提交频率；事件不含硬件／VSync 标志，不能认证物理扫描输出、输入延迟或逐提交显示率。[Chromium 源码](https://chromium.googlesource.com/chromium/src/+/HEAD/components/viz/service/display/display.cc)
- 便携 PresentMon 2.6.0 的实际 ETW 尝试退出码 6，当前普通账户缺少访问权限。保留二进制摘要及错误日志；未提权、安装服务或更改用户组。Windows ETW／硬件呈现证据仍缺失。[官方权限说明](https://github.com/GameTechDev/PresentMon/blob/main/README-ConsoleApplication.md)

## 复现

先 `npm run build`。生成最新成品可运行 `node scripts/verify-production-card.mts`，原生检查设置 `GODOT_BIN` 后运行 `node scripts/verify-production-godot.mts`。不要在测量进程仍运行时重建 dist，也不要与其他图形测试并行。

```powershell
node scripts/measure-card-performance.mts --adaptive --counts=16 --modes=small,adaptive --seconds=12 --presentation-trace
node scripts/measure-card-performance.mts --adaptive --soak-only --soak-count=16 --soak-mode=small --soak=600
npm run test:benchmark-device
npm run benchmark:device:serve
```

验收页面支持 1／4／8／16 卡、原图／高清／小图保留特效／自动、三种动作、音效、换档、暂停、释放和保存 JSON。默认服务仅本机 `http://127.0.0.1:8788/`。有手机后可显式用 `--host=0.0.0.0` 在同一局域网复现；当前桌面窄视口检查不能代替手机性能或触控验收。Windows 硬件呈现、稳定完整效果十六卡预算、更多启动样本和全部 P2 清单继续保留。
