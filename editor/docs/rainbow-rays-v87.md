# 彩虹旋涡：条带与反光分开校准

已重新核对 SnapFan 的 RaysRainbow 页面和本地公开短片。参考为 820×1100、77 帧、2310 ms，SHA256 `77313ccefc26ca3fb623b2d8cd58152cf0e28b11f04b57b81e5d972714a5eafe`。条带缓慢旋转，浅银条带上出现粉、青和少量暖色的反光；不是让整个背景均匀变色。原画、数字、灰色翅膀和外框不属于本次表面校准。

先用固定的暴露背景多边形规划条带中心、弯曲和旋转。颜色规划分别观察浅色条带和暗底；用少量连续函数表达色膜与银色高光，不能逐帧抄写游戏贴图或用色盘替换冒充匹配。当前 `raysrainbow` 基线完整保存于独立 QA 目录，紫色和其他材质保持原状。

设计候选须先采集真实 GPU 的整段 77 帧，再比较相同预选区域的条带分类、RGB 差和逐帧变化。七个均匀时刻用于规划，其余 70 帧用于检验，固定区域和源像素门限不随候选表现调整。配准只是近似内窗坐标，不能据区域误差宣称全卡 1:1。

验证后才采用正式样式。时间推进、暂停、零速、相机倾斜、替换背景与叠加原画应通过实际 SDK 导出场景检查；版本和覆盖表记录真实结果。活跃工坊、人物素材、Mask 与卡背不直接改写。完整 Snap 动效和每类至少 50 个原创继续作为未完成目标。

参考：[RaysRainbow](https://snap.fan/cosmetics/split-effects/RaysRainbow/)。短公开展示不能证明完整游戏循环或全角度一致。

## 候选比较与运动量测

固定五个暴露区域、6097 个源像素位置，源帧亮度高于 100 判为浅条带、低于 55 判为暗底，中间值不参与分类。每帧采用相同源门限，区域与点位不随候选改变。GPU 分类门限为两者中点 77.5。图与原始指标为 `outputs/rays-v87/gpu-*-comparison.json/.png`。

逐步比较基线、旋转几何、反光、径向弯曲、平滑转速四个阶段；每个阶段实际采集基线与候选各 77 帧，没有复制既有帧冒充新渲染。所有 PNG 有 Shader 哈希、参数、帧号与完整性记录。

| 77 帧固定区域 | 原基线 | 最终候选 |
|---|---:|---:|
| 平均条带分类误差 | 0.49934 | 0.18438 |
| 平均 RGB 绝对差 / 255 | 91.417 | 45.213 |
| 相邻帧 RGB 变化差 / 255 | 4.712 | 7.954 |

条带位置误差约减少 63%，颜色差约减少 50.5%。相邻帧像素变化指标仍比静态基线大，不能隐去或声称逐帧像素运动已经一致：它同时受到未匹配的条带初始位置、遮挡与颜色影响，静态图也可能得到较小的这个数值。

为明确旋转本身，另从真实 PNG 的条带轮廓逐帧量测相位，使用每组自己的几何，移除各自初始相位后比较角度推进。此指标只评估推进，几何位置与颜色仍由上表独立评估。源轮廓通过近似几何观测，保留遮挡污染，不是恢复了游戏参数。数据为 `gpu-eased-phase.json`、`gpu-linear-phase.json`。

| 旋转推进 | 静态基线 | 匀速候选 | 最终平滑候选 |
|---|---:|---:|---:|
| 77 帧角度推进 RMS / ° | 7.389 | 0.924 | 0.219 |
| 未参与规划的 70 帧 RMS / ° | 7.335 | 0.932 | 0.222 |
| 六段速度差 RMS / °/s | 6.071 | 1.117 | 0.626 |

采用恒定角度推进加有界正弦调制，而不是在观察短片之外无限增长的三次多项式。此公式没有逐帧查表或贴图抄写。空间银色反射与粉青色膜各用连续波表达，查看角度改变反光，播放时间同时驱动条带与反光；没有增加贴图、遮罩或绘制表面。

## 正式实现与验证

`raysrainbow` 继续使用编号 27 与同一个效果库配方 `material-rainbow-rays`。新增独立 `finishRainbowRay` 函数；紫色、通用色带与其他材料的公式保持原状。已有彩虹配方在源码与构建 0.19.87 中使用新动态，不需要迁移工程格式。活跃工坊没有直接改写，独立桌面窗口本轮未重启。

正式生产函数再次实际采集 77 帧，全部 RGB 像素与最终候选相同，最大通道差零，见 `production-candidate-pixel-parity.json`。总计 693 个 GPU 帧来自四组基线／候选比较与一组正式生产采集。`production-motion.webp` 只是 2310 ms 的实际渲染片段，无损打包，不代表整个 Shader 周期。

29 项配方、共享函数、保存重开、组件发布、本地背景和原创回归通过；构建与语法检查通过 202 文件，新增 Python 校准工具另外通过语法检查。独立验证卡通过当前 `exportGodot` 正式导出，一张卡、零素材贴图；三个 SDK 核心文件与当前源文件逐字节相同，见 `godot-source-equality.json`。

实际 SDK 场景的验证记录在 `godot-runtime.log` 和 `godot-runtime-captures/`：时间推进产生可见变化，暂停像素稳定，零速冻结，相机倾斜响应，替换隐藏源图、叠加恢复源图。此场景证明一项配方的运行与组合，不代表全部效果或完整游戏相机的验收。

## 六种其他色系的参考缺口

重新读取各公开详情页实际链接并下载了蓝、绿、粉、红、黑白、橙六种短片。检查的 0、26、52、76 帧均只有普通 Wasp 原画，没有对应放射条带，不能用这些画面校准指定色系。原文件、哈希、帧数与观察保存在 `other-rays-metadata.json`，覆盖表明确设为不可作为指定效果参考；既有原型仍保留待修，没有套用彩虹／紫色结果标记为已还原。

官方 [2026-05-19 更新说明](https://marvelsnap.com/patch-notes-may-19th-2026/) 明确保留既有 Rays 分裂卡，只将 Rays 从后续分裂池移除。因此仍保留全部历史效果在目标范围中；不能以生命周期变化为由删除未还原项，也不能据此推定上述公开预览失效的原因。

本轮没有新增原创计数。覆盖仍为 237 项、0 项完整 1:1 验收；全量边框、粒子、背景与每类至少 50 个原创设计／实现继续未完成。
