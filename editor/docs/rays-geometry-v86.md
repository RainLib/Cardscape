# 紫色旋涡放射：静态条带校准

## 设计依据

已核对 `RaysPurple-motion.webp` 的真实像素：820×1100，77 帧，2310 ms，SHA256 为 `49b15179848593f242530d513a4eed8bc5d22024d52136ef6e1c73d1c9cb6446`。画面包含黑底和固定紫色放射条带，人物、翅膀与数字遮挡了大量背景。图案的拓扑与反射分别校准，不能用播放亮度变化代替形状一致。

当前 `finishRay` 的中心为 (0.35, 0.90)，弯曲系数为 1.10，默认 32 条带。先选定五个暴露背景区域，再用固定颜色门限识别紫色与暗色，避开灰色翅膀、服装和霓虹框。区域、所有 3475 个取样点和遮挡局限保存在 `outputs/rays-v86/geometry-prediction.json`、`source-geometry-samples.png`；不因候选的结果改变区域或删去不利点。

源像素的几何预测提出候选：中心 (0.5256, 0.7830)，弯曲系数 0.7981，默认 31 条带，相位 1.8545。预测的紫／暗均衡分类误差从 0.4274 降到 0.1654，但这仍是固定帧的数学预测，不是 GPU 验收。内窗配准采用 (103,151)、632×899，不是恢复了源游戏的真实相机。

## 先验证，再应用

生成独立基线与候选 Shader，不改活跃工坊。使用实际生产表面函数，渲染两组完整 77 帧，并在固定的同一批源取样点上比较条带位置和亮度；再检查 0、26、52、76 帧的区域误差，防止仅拟合一个时刻。视角变化、暂停、零速、覆盖原画与叠加原画继续由实际 Godot 导出测试检查。

初始方案只改变固定几何，假设时间／视角负责反光。该假设必须由整段序列检验；发现条带运动后按真实观测修正。保持材质频率可编辑、原画和 Mask 不变、单表面绘制。紫色参考先验证；其他调色板及幻彩效果不得仅凭紫色结果标记为已还原。全量 1:1、每类 50 个原创和后续编辑器优化保持原目标。

## 连续帧否定了静态假设

两组实际共享表面函数 GPU 帧均采集成功，首帧非空。第 26 帧的条带分类误差由 0.426 降至 0.170，但整个 77 帧的平均误差只由 0.482 降至 0.461；候选第 65 帧误差反而到 0.714。不能据此将单帧候选应用到正式材质。

在同一批固定源区域逐帧寻找条带相位，发现相位持续前进：第 0 / 26 / 52 / 76 帧的展开相位约为 0.209 / 1.885 / 4.206 / 6.327。线性预测速率为 2.64036 rad/s、残差 RMS 0.13617 rad。说明当前序列中条带本身缓慢旋转，不只是改变反光。该速率是条带相位，在默认 31 条带时约为 4.88°/s 的图案角度；不是恢复了原引擎参数或证明完整游戏周期。

接下来在 0、13、26、39、52、65、76 七帧联合规划中心、弯曲、条带数、初始相位与相位速率，再采集完整 GPU 序列，检验未参与规划的 70 帧。暂停／零速冻结条带和反光；视角与颜色仍独立。计划参数与源区域保持可检查，不能用逐帧复写源像素代替 Shader 动态。

七帧联合预测提出：中心 (0.54045,0.77825)，弯曲 0.71275，默认 31 条带，初始相位 −0.95193、相位速率 2.57032 rad/s。在材质默认 speed=0.35 下，将图案角速度取整为每个材质时钟 0.23690 rad；频率改变条带数量但保持角速度。联合预测分类误差为 0.20072，仅用于下一次候选设计，不作为 GPU 或 1:1 验收。

正式采用时将紫色参考使用独立 `rayspurple` 材质样式，追加枚举并保持全部旧编号。`rays` 继续保存既有通用色带能力，其他颜色与 `raysrainbow` 先保留原公式，避免未经对应参考核对就改动整个系列。紫色效果库入口保留相同配方 ID，使用共用的新旋转函数；没有新贴图或额外表面提交。新样式必须再次通过生产共享函数一致性和真实 SDK 场景的验证。

## 0.19.86 实际采用结果

两组完整 GPU 序列各 77 帧，使用同一清晰区域、取样间隔、颜色门限与内窗配准。未参与联合规划的 70 帧也包含在正式比较中。基线和旋转候选分别来自实际 PNG，输入 Shader 哈希、首帧非空与完整帧数检查通过。

| 固定区域量测 | 基线 | 旋转候选 |
|---|---:|---:|
| 77 帧平均条带分类误差 | 0.48176 | 0.19510 |
| 分类误差 P10 / P50 / P90 | 0.41435 / 0.49642 / 0.54410 | 0.17095 / 0.18252 / 0.23811 |
| 平均 RGB 绝对差 / 255 | 76.927 | 42.594 |

分类误差减少约 59.5%，颜色差减少约 44.6%；0、13、26、39、52、65、76 的每个检查帧都有改善。测的是预选暴露区域，不是整卡还原百分比；灰色翅膀、遮挡、源相机、反光颜色与完整游戏周期仍未匹配。数据为 `gpu-animated-comparison.json`，图为同名 PNG。

正式 Shader 使用独立的 `finishRayMotion`，`rayspurple` 追加为编号 29；旧 `rays=14`、`raysrainbow=27`、`caustics=28` 与所有更早编号保持不变。效果库中的 `material-rays`、`material-purple-rays` 指向新样式，其他色系仍使用旧公式。材质面板保留“紫色旋涡放射”入口，并为旧样式显示“通用旋涡放射”，避免旧工程被错误描述成粉色。

正式生产函数又独立渲染 77 帧；新样式编号 29 与先前候选的全部像素逐帧相同，最大通道差为零，见 `production-candidate-pixel-parity.json`。合计实际采集 385 帧：单帧几何方案两组、连续旋转方案两组、生产样式一组；没有将 CPU 预测或拷贝 PNG 当作新 GPU 帧。

29 项材质、配方、保存／重开、组件发布、本地背景与原创回归通过。构建与语法检查通过 201 文件；面板标签随后单独通过语法检查，差异空白检查通过。

通过当前 `exportGodot` 真实导出独立验证卡（一张卡、零纹理），三个 SDK 核心文件逐字节匹配源文件，见 `godot-source-equality.json`。实际 CardscapeCard 运行 `test_surface_reference.gd --recipe material-purple-rays`，GPU Shader 错误为零；验证时间推进、暂停像素稳定、零速冻结、替换隐藏源图、叠加保留源图。日志为 `godot-runtime.log`，截图为 `godot-runtime-captures/`，导出为 `godot-runtime/godot/`。6.212 秒是验证任务耗时，不是实时 FPS。

本轮没有替换当前活跃卡片或重启独立 Electron 窗口。源码与构建版本为 0.19.86，桌面是否已加载新版本不作为已验证事实。覆盖仍为 237 项、0 项完整 1:1 验收；本轮不增加原创计数，仍需完成全量 Snap 和每类至少 50 个原创后再进行既定编辑器优化。
