# 参考校准：Tone、Gold、Metallic Gold

参考检索：2026-10-12。使用 Snap.Fan 的公开动态渲染，并以 Marvel Snap 官方的 Finishes/Flares 分类为范围依据。素材只保存在参考目录，不加入产品资产或 Godot 导出。

## 可确认的视觉差异

- **Blue Tone**：框外有成片的斜向半调圆点，大小与密度形成渐隐。参考中还存在掠过卡面的细亮线。目前先修正网点主形；亮线及揭示阶段仍待专门校准。
- **Gold Glimmer**：最初的放射闪光与后续缓慢浮动的小金色闪片是两个阶段。现有持续星芒不能视作相同动画；需后续增加揭示事件和独立的持续阶段。
- **Gold Finish**：背景转为金色，仍可辨认原图的明暗和轮廓。将它当作纯程序色块替换会丢失这些信息。新默认使用背景色调映射，保留原图明暗；完全覆盖背景仍可通过 replace 选择。
- **Metallic Gold Border**：平直的切角框有两条窄亮边、中槽暗部和随观看角度改变的高光。它不靠弯曲产生立体感。

## 实现约束

Tone 采用单个 quad 内的圆点网格，沿已有框轮廓分布，22 个实例；不为每个网点增加节点。沿用一批次、一张共享缓冲和固定预算。原有 `sprite` 和其他外观枚举索引保持不变。

Gold 在选中的背景范围内使用原图亮度形成金色浮雕细节，再叠加宽反射带。人物、数值和字标不参与此默认映射。金属边框通过横向亮脊／暗槽曲线及视角控制反射，框体几何仍为刚性平面。

WebGL 与 Godot 使用相同 finish/rim 函数和对应的粒子图形；编辑器和游戏均不需要大张序列贴图。

## 证据边界

这些 WebP 只有约 2.3 秒，不能证明完整游戏待机或揭示动画周期。因此以上调整仍是待校准实现，未计入 1:1 验收。它们也不替代对其他特效系列的逐项验证。

## 导出实画发现的遮挡缺陷

Godot 的透明人物图层使用负的绘制优先级，原先 `behind` 粒子优先级为 -10，实际会晚于披风绘制，造成卡后网点压在人物上。已将卡后批次移到所有卡面表面之前（-120），前景覆盖仍为 120；它们仍保留原来的物理深度与相机视差。GPU 验证增加了粒子优先级必须低于每个卡面表面的检查，并重新拍摄实际导出画面。
