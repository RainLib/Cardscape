# 卡牌工坊制作

把用户的大致想法变成可继续编辑的卡片。保留原始要求、已完成素材和执行回执，按当前工程状态推进，直到所要求的制作和验证完成。

## 先读取现场

- 在客户端任务目录读取 `contract.json`：当前卡片、图层 ID、共享资源、实际 Mask 统计与附图、就绪图片任务、制作目标和历史回执都来自这里。操作格式以 `editorCommands` 为准；不要从旧消息复制已失效的坐标或资源 ID。
- 客户端默认注入本 skill，终端可用 `$card-atelier` 发现它。若终端没有工坊契约或可操作的连接，先说明需要在工坊 AI 助手中执行，或询问用户提供哪个已连接的工程；不能直接改写活跃工程文件来冒充客户端操作。
- 若契约 schema 为 `card-atelier-agent/1`，当前是图片子任务：只按该图片契约调用真实图像工具并写产出清单，不提交编辑指令或 question 块；缺少图像能力时按契约返回 unavailable。
- 沿用 Agent CLI 的模型、推理与登录配置。能力缺失时报告实际错误和恢复入口，不猜模型权限，不改全局配置，也不把占位图当生成成功。

## 决策与提问

遇到影响卡片身份、风格、素材授权范围、语言版本或制作方向的歧义，使用 question 先问用户。已有答案不再问，明确可推断的排版与技术参数自行处理。每次只问当前真正阻塞的 1–3 项，优先给 2–3 个短选项，同时允许自由输入。

客户端通过 `<atelier-question>` 显示问题，详见 [提问协议](references/questions.md)。发出问题后结束本阶段，不同时提交编辑指令；没有回答就不继续依赖它的制作。回答保存在下一次契约的 `questionAnswer` 与历史回执中，从最新工程恢复，保留此前成果。CLI 的 `exec` 没有交互式 question 工具时必须使用此协议，不能在文字中问完自己选答案。

## 制作与验收

按用户实际范围选择步骤。完整新卡通常依次完成构图、素材生成、背景与连续人物、区域 Mask、文字、效果和整卡动画；细化现有卡只做需要的部分。具体注册关系、刚性保护与检查方法见 [制作约定](references/production.md)。用户要求多层景深/相机视差时，读取 [空间图层约定](references/spatial-depth.md)，先确认需要的远/中/近景与人物部件，保留完整母版与连接点；使用契约支持的图层组与 Slot，不假定未来的相机接口已经实现。

- 将新增卡片、图片任务和共享资源绑定作为独立阶段，收到应用回执后使用新上下文继续。图片任务必须实际 READY 才能导入。无需用户决定的技术问题自行修复。
- 只返回契约支持的声明式操作，交给客户端原子应用、撤销和版本校验。不要执行脚本去修改活跃图层、编造任务或跳过过期保护。一个阶段最多一批 `<atelier-actions>`。
- 客户端每个成功制作阶段自动写入独立检查点，不改原工程的保存状态。重开后若当前像素与历史回执不一致，使用 AI 面板“恢复制作”，核对最新上下文再继续；不要把上次仅在内存中的成功回执当作已保存素材。
- 依据 `editorResult` 区分“已提交”与“已应用”。如果批次被拒绝，保留已生成素材，用最新上下文修正参数；同一阻塞反复发生时说明缺少的能力，不无限重试或重新生成全部素材。
- 阶段性检查真实像素和 Mask、正面及倾斜构图、语言切换、效果范围、编译回执与播放状态。无法从当前契约观察的验收必须明确待客户端确认，不能宣称看到了未提供的预览。
- 完成后简短报告已做内容、实际验证与剩余项，给出保存/导出入口。仅在用户要求的内容全部完成后停止连续制作；不要把“没有指令”当作省略未完成步骤的理由。
